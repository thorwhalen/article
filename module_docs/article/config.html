article.config

Domain schema + configuration facade.

Two concerns live here, both expressed as Pydantic v2 models so validation is declarative and the SSOT for shape:

  1. The article domain model (Article + the per-platform config models) — parsed from a standardized JSON file via load_article(), which turns raw Pydantic tracebacks into a single actionable message (which field, why).

  2. Runtime settings/secrets (Settings) — API tokens and Substack credentials loaded from .env / the environment via load_settings(), the single facade the rest of the package calls. Secrets are marked repr=False so they never leak into logs or tracebacks.

Per-platform presence is the on/off switch: a platform absent from article.platforms is simply skipped.

secrets_for(platform: Literal['substack', 'medium', 'dev_to', 'hashnode']) → dict[str, Any][source]

The minimal secrets/identity an adapter needs — injected, not global.

Returning only the relevant subset keeps adapters from reaching into a global Settings (dependency injection + least privilege).

>>> s.secrets_for("medium") == {"token": "t", "user_id": "u"}

article.config.load_article(source: str | PathLike | Mapping[str, Any]) → Article[source]

Load and validate an Article from a JSON file path, JSON string, or mapping.

Validation failures are re-raised as ArticleValidationError with a single message naming each offending field — not a raw traceback.

>>> load_article({
...     "title": "Hello",
...     "slug": "hello-world",
...     "content_markdown": "x",
...     "platforms": {"dev_to": {}},
... }).slug
'hello-world'

>>> load_article({"title": "x"})
Traceback (most recent call last):
...
article.base.ArticleValidationError: Invalid article ...slug... content_markdown...

>>> load_article({"title": "x", "slug": "Bad Slug", "content_markdown": "y"})

...
